A whole testing cycle, one example

From a new QA repo to a closed release

What you run, what the harness asks you, and what comes out at each step. Written for someone who has never tested this way, manually or automatically.

IllustrationThis follows what each agent is written to do. The harness has not yet been run end to end against a real application, so the first project will show where it differs.

Application

An online store, QA environment

Jira

Kinds of user

Ticket to test

Setup: the context-builder learns the application

/playwright-context-builder runs once, after the files are copied into the new QA repo. It stops at every checkpoint and waits for you. It runs again only when the application changes.

4Report the whole cycle

The harness asks

The record keeps each case's latest result, so a test healed after the regression counts as passing. --since stops last cycle's passes from counting in this one.

TRACE

One test case through everything: ACME-1234-TC006

The test case ID never changes. It is what ties the ticket, the test, the result and the bug together, and what lets anyone in Jira walk back to the requirement.

Requirement

ACME-1234, AC2: removing the code restores the total

Test case

Plan heading ACME-1234-TC006 — Validate that…, Priority 1

Test code

The test title starts with ACME-1234-TC006

Result

Failed on build rc2, in automated-results.csv

Defect

Defect log entry, screenshots kept

Jira bug

ACME-1302, label ACME-1234-TC006, linked to the story

Retest

Passed twice on rc3. Verified; AC2 covered again

ALREADY HAVE

Existing test cases and test data

Old test cases are a head start, not a finished plan. Each one is checked against the current ticket and gets a new test case ID. The plan keeps a table mapping old ID to new, so the old copy can be retired.

What you haveWhere it goesHow it is used
Test-case sheets, test-tool exportscontext/sources/ as CSVSummarized per area as existing coverage. Point the planner at the rows to carry them into a plan
An older automated suiteStays where it is; export its list of casesThe same. Its code is not converted; the generator writes fresh code by driving the app
Old features with no ticketA plan under the story or epic that introduced them, or a ticket raised for that areaOne plan per area, starting with what the next release touches
QA test accounts.env, one pair per roleThe login files
Records the tests rely ondata/testData.ts keysEach test case's Data field. Never typed into a test
Seed and reset scriptsdata/sql_queries.ts, called from data/seed.tsRun before every run with SEED_TEST_DATA=true
Personal data, production extractsNowhere in the repoNot used
